# 额度雷达

项目仓库：https://github.com/tomczhang/qdii-radar

本机开发目录：`/Users/tomczhang/Documents/git/qdii-radar`。原 Codex 工作目录保留作迁移前备份；日常开发和服务启动使用本目录。

国内纳斯达克100、标普500 QDII 基金的真实额度看板。React + Express + SQLite，同一服务提供响应式页面、数据 API 和公告更新任务；邮箱订阅实现保留，首版隐藏通知入口。2026-10-15 核验名单包含 **55 个场外人民币份额、16 只场内 ETF**，两个板块独立展示。`server/catalog.json` 为已核验种子名单；动态发现的份额持久化在 SQLite 中，无需改代码或重启。范围不包含美元份额、纳斯达克科技/生物科技、标普500等权等不同标的。

## 运行

要求 Node.js 24（使用内置 SQLite）。

```sh
npm install
# 首次安装且不存在 .env 时执行；不要覆盖已有配置
cp .env.example .env
npm run dev
```

打开 http://localhost:4387 。生产运行：

```sh
npm run build
npm start
```

`.env` 配置服务端地址、Resend/SMTP、管理员令牌和可选聚源 MCP。`ADMIN_TOKEN` 应使用随机长字符串。密钥不能使用 `VITE_` 前缀。当前本地 `.env` 已生成管理员令牌；不要提交该文件。

账号体系见 [额度雷达独立账号](docs/accounts.md)。填写昵称、邮箱和密码注册，点击邮件链接激活；登录使用邮箱＋密码，找回密码同样使用邮件链接，不再跳转统一账号中心。邮件未配置时保持免登录可用，收藏和计算方案仍仅保存在当前浏览器。

## 数据来源与口径

微信小程序可通过 AnyService 服务 `dashboard` 调用 `GET /api/dashboard`，免登录获取与网站相同的数据。配置、返回字段与可复制的调用代码见 [小程序看板接口](docs/anyservice-dashboard.md)。

| 数据 | 当前来源 | 处理 |
|---|---|---|
| 代销状态、单日上限 | 天天基金 `FundMNBasicInformation` | 暂停优先于残留额度；不销售与暂停分开；缺失或哨兵值不当作无限额 |
| 近1、3、5年累计收益 | `FundMNPeriodIncrease` | 使用接口收益截止日期；不足年限留空，不按年化展示 |
| 近30个净值日走势 | `FundMNHisNetList` | 链接每日净值增长率，基准100；缺失时截取最近连续数据，上游小数舍入会产生误差 |
| 直销额度 | 基金公司公告，当前经天天基金公告索引/PDF镜像获取 | 存公告原文、份额、渠道、生效时间与提取依据 |
| 主收益与净值来源（配置后） | 恒生聚源 MCP `FinQuery` | 校验基金代码、人民币份额、成立日期、收益日期与净值；更新收益、走势和对应日涨幅，失败回退天天并标明来源 |

公告列表端点：`https://api.fund.eastmoney.com/f10/JJGG`，正文 PDF 来源：`https://pdf.dfcfw.com/pdf/H2_<公告ID>_1.pdf`。这不是已签约的数据 SLA，也不是逐个基金公司官网爬虫；公告镜像有延迟或故障时会显示更新时间/待核验。生产公开展示所需的数据使用授权需另行确认。

不同基金的收益、净值截止日可能不同，页面分别标注。额度是公告/销售渠道的账户单日上限，不是个人剩余额度，也不能默认跨渠道、跨份额累加。已有直销规则以已核验公告建立基线，保存在 `server/verified-baseline.json`，后续新公告按实际生效时间覆盖。

## 数据兜底

- 天天的额度、收益、走势端点分别处理；收益失败不丢弃已经取得的额度，走势和日涨幅保持同一净值日期。
- 聚源与天天独立请求。聚源失败后退避重试一次；天天网络请求已有最多三次重试。任一合格来源可用就正常展示，备用成功不判为整轮失败。
- 按字段组保留最新成功数据；不会让较旧来源覆盖较新日期，也不会用新的收益采集时间刷新旧额度的时间。两源都失败时保留缓存；从未取得的字段保持未知。
- ETF溢价率批量查询后只重查失败代码一次，仍失败保留原有行情及交易日，不混用滞后净值冒充实时溢价率。
- 来源诊断保存在本地 `meta.sourceHealth:<代码>`。前台只提醒具体缺失/过期的数据：超过36小时未验证，或净值/收益日期落后交易日历超过2个交易日（收盘溢价率要求覆盖最近已完成交易日）；正常切换来源不显示故障横幅。份额未满1/3/5年的空值不当成故障。
- 公告继续使用请求重试、正文缓存和已核验规则；发现新公告含糊时，额度保持待确认，不猜测额度。

## 聚源 MCP 接入

已实测官方地址支持 **Streamable HTTP**，Token 使用查询参数认证；代码在发请求时从环境变量组合，配置 URL 本身不含密钥：

```dotenv
GILDATA_MCP_URL=https://api.gildata.com/mcp-servers/aidata-assistant-srv-tool
GILDATA_MCP_TOKEN=<你的Token>
GILDATA_MCP_TRANSPORT=http
GILDATA_MCP_AUTH=query
```

仅填 Token 也会使用上述默认地址。兼容其他服务配置的 `sse` 传输和 `bearer` 认证，但当前官方地址已验证使用 `http` + `query`。用 SDK `initialize`/`tools/list` 确认工具，再调用 `FinQuery`；不在浏览器直连 MCP。超时或返回不符合约定时回退天天数据，并记录每个份额的失败状态。

2026-10-15 全量实测71个代码均取得真实收益/净值；首轮67个聚源成功、4个使用天天回退，单独重试后71个均通过聚源数据校验。当前收益截止日为2026-10-14。71个代码的同截止日可比较1/3/5年累计收益与天天基金交叉核对，未发现超过0.02个百分点的差异。此结论仅对应本次数据，不能代替持续核验。供应商数值不作为直销额度证据：代销继续取天天，直销继续按基金公司公告。

收益按一组、净值/日涨幅/走势按另一组整体选择较新来源，页面分别显示来源和截止日期。拒绝错误代码、未来日期、缺失成熟区间、冲突净值；不满对应年限的收益留空。同步结果提供 `gildataSuccess` / `gildataErrors`，看板提供实际使用聚源的份额数；“已配置”不冒充“成功取数”。

## 自动发现基金份额

每日同步先读取天天基金 `fundcode_search.js` 全量目录（仅 JSON 解析，不执行脚本），对“纳斯达克 / 纳指 / 标普500 / 标准普尔500”名称候选读取 `jbgk_<代码>.html` 基金档案，核验代码、管理人、跟踪标的和产品类型。简称缺少“100”的 ETF 也会被发现；联接不会因为名字带 ETF 就被归入场内。天弘标普500 FOF 按名称及业绩基准单独核验。

新增/改名份额当天复核，已核验档案每7天复核；按代码去重并持久化，原目录消失或来源失败不自动删除旧基金。异常目录缩减及核验失败会记录状态并重试。新份额进入同一轮真实行情和公告同步，额度未知时显示待核验，不复制同公司/同基金其他份额的金额。首次观察不生成额度变化提醒。名单日期、场内外数量和异常状态在页面底部展示。

场内 ETF 的二级市场交易不套用“代销/直销元/日”额度，也不发送场外额度提醒。页面使用可横向滚动的表格，默认按溢价率升序，也可点击表头或下拉框切换。聚源 `FinQuery` 的“场内基金日行情”提供收盘价、场内日涨跌及**收盘折溢价率**，每行标注交易日；这不是盘中实时 IOPV 估值。近1/3/5年仍为净值累计收益，与价格涨跌分开。行情缺失显示空值，失败保留之前的值及日期；一级市场的当日申赎额度以基金公司 PCF 为准，本版只提供申赎公告入口，不把天天基金不销售误标为交易所不能买。场外 LOF 份额仍放在场外申购板块。

## 每日公告任务

服务运行期间，每日 **07:30 和 16:30（Asia/Shanghai）** 同步全部份额的额度、收益、净值和公告，早间时间可用 `DAILY_SYNC_TIME` 调整。启动时补做当天错过的任务；部分失败15分钟后重试。两次观测仍不能保证捕获盘中所有短暂变化。场内收盘行情与境内交易日期单独保存同步状态，启动时及每天更新，失败15分钟后重试。

同步按阶段执行：先检查基金名单，再以最多3只并发采集全部基金的天天额度、收益和净值，每只完成立即保存并更新看板时间；随后核查当前公告、记录额度变化与当日观测，再逐只用聚源补充收益和走势。聚源阶段复用本轮天天结果，不重复请求，也不改变额度字段的原始观测时间。最后更新场内行情/交易日历、近30天额度动态和历史额度倒推。首次同步先展示可用的当前数据，历史补录不再挡住额度展示；仍保留字段级来源选择、失败回退和旧日期保护。

公告流程：

1. 逐份额分页获取全部类型公告，再筛选申购/定投/转换转入限制、恢复和暂停公告。
2. 以“公告ID + 基金代码”去重，保存PDF及文本；至少重叠回查14天，停机较久则从上次扫描日回溯。超过单轮分页上限，保存游标，下轮重查首页并从重叠分页继续。
3. 解析明确的代码、份额、渠道、金额和生效日期。存在扫描PDF、多个日期、特定投资者、渠道细分、交易截止时间等歧义时进入 `pending_review`。正文失败单独重试，不因滚出列表窗口而丢失。
4. 未来规则先入库，随每日两次同步（以及启动补抓、失败重试）检查并记录到期变更，不再单独每分钟检查。尚未生效时不提前改额度。新公告待核验时直销显示“待核验”，不会继续宣称旧额度已确认。
5. 与最近确认的状态比较，记录恢复/增加/降低/暂停，持久化提醒队列。首次同步只建基线；重复扫描不重复生成变化。同一浏览器同一邮箱的全局和单基金订阅合并去重。
6. 保留失败前的数据和时间；超过36小时无成功数据/公告扫描会提示待更新。任务、队列有数据库锁和失败重试。

手动同步：

```sh
npm run sync
npm run sync -- --notices-only
```

这属于网站服务内部任务，需要服务器持续运行。关闭进程或电脑休眠期间不执行；启动后补抓。无需 Codex 对话自动化。

## 近30天额度动态

按北京时间含今天的30个自然日，按规则生效日期筛选。`server/change-history.mjs` 在每日同步和启动补抓中独立回查公告；向前多扫描7天以覆盖提前公告、后续生效的规则，不因现行额度已有人工基线而跳过历史公告。每份额最多回查5页，未到窗口边界或正文失败时标为部分覆盖并重试。更早发布、很晚才生效且从未入库的公告仍可能遗漏，覆盖状态反映本次扫描范围，并非全量历史保证。

已核验历史存入 `changeHistory:records`，不创建邮件事件、不改写每日额度快照。同一公告的各份额分别计数；与当日同份额、同渠道、同结果的实时观察去重。无法验证原额度时明确标注“原额度未核验”；未完成历史核验且无记录时显示“— / 历史待核验”，不误报0。公告来源和生效日期均可查看。

首次补录核验了广发10月13日恢复、10月15日暂停，以及招商10月14日暂停，共8条份额动态。人工核验条目在 `server/verified-change-history.json`，绑定公告正文SHA-256；正文变化不会沿用旧核验结果。一般明确规则自动解析，歧义公告列为待核验。

## 收益、走势与20个交易日额度

场外“收益与走势”统一展示代销/直销的当前额度、20交易日累计额度、开放天数和覆盖天数，并列近1/3/5年涨幅与走势；手机卡片包含同样指标，不再切换独立的稳定性表。累计排序优先覆盖天数，再按金额排序；不把只有1天的数据与完整20个交易日当成同等样本。

- 窗口：最近20个已完成的境内交易日（约一个月），不含今天。使用东方财富上证指数实际日线日期，剔除重复及未来日期；不用周一至周五代替真实交易日历。日历不足20日或超过36小时未校验时标为待更新。
- 每次成功同步及已知规则生效时，按份额、渠道、上海日期持久化最后一次观测。当天源未更新则不复制旧日数据；周末记录不会纳入交易日窗口。
- 暂停/该渠道不可买计0；未知或漏采不计0。`knownTotal` 是已知日期之和；仅覆盖全部20日且日历有效时 `total` 才非空。两个渠道不相加。
- 一次性导入旧版本中已有的、无待核验/过期标记的发布观测。只恢复其真实观测日，不用当前规则补造过去20个交易日。观测不足的日期由独立的公告倒推流程补充，并保留推算标记。
- 实测历史保存在 SQLite `quota_daily`，公告推算单独保存在 `quota_estimates`；行情保存在 `meta` 的 `etfQuote:<代码>`，接口 `/api/dashboard` 分别返回每只基金的 `stability` 或 `quote`。请持久化 `.data` 目录，否则重建服务会丢失历史。

旧30日窗口核验示例（000834，2026-08-27 至2026-10-15窗口）：代销累计290元、直销2900元；每个渠道覆盖30日，其中实测1日、公告推算29日，开放29日。限额依据6月4日生效的公告，9月7日按年度休市公告暂停计0。累计上限不是个人剩余额度或可保证投入金额；额度开放稳定性也不代表基金收益稳定性。

### 公告倒推与更新

- `server/reconstruction.mjs` 每天及数据同步时回查公告；从窗口起点再向前查365日寻找有效起始规则，分页最多20页，正文按公告ID缓存。未完整扫描时不使用该份额推算。
- 按渠道、份额、生效日期重建时间线；恢复、暂停、额度调整各自生效。节假日覆盖日限额，节后恢复原有规则，不能解除另一个公告规定的长期暂停。年度复杂表格在 `verified-holidays.json` 核验，特殊金额条款在 `verified-history-rules.json` 核验，绑定正文SHA-256和适用份额；未知表格保留待核验。核验表过期不会套用下一年度。
- 实际记录优先（包括明确未知的观测）；只给没有观测的日期补推算。缺少起始规则、正文失败、冲突或范围含糊时保持未知。倒推结果不会更改当前额度、真实观测、近期事件或产生历史提醒邮件。
- `stability` 返回 `observedDays`、`inferredDays`、`missingDays` 与逐段 `segments`（日期、额度、来源、公告链接）；详情可展开依据。`complete` 仅表示覆盖完整，不代表20日都是实测。
- 首次补录覆盖程度因公告而异；未核验的区间保持未知。新增或修订的公告、人工核验可以改变推算，实测记录始终保留。
- 定时任务随服务运行；需要常驻进程，并持久化 `.data`。暂停服务会漏采，重新启动会回查公告，但无法恢复销售平台当时的实际临时限制。

南方纳指I（021000）纠正：7月20日公告明确自7月21日起每日200元，个人与非个人的处理方式不同，但上限相同。在旧窗口2026-08-27至10-15的30个境内交易日中，扣除年度安排规定的9月7日暂停，直销累计5800元。以前仅显示采集到1天的200元，因为严格解析器未接受该复杂公告；现在用绑定正文SHA-256的核验规则补齐。只应用I份额，不移植到A/C，也不把直销额度当成代销可购买证明。历史扫描同时纳入标题仅写“节假日申购赎回安排”、未写“暂停”的公告。

## 商业化与首版范围

2026-10-16 决定：站内额度查询、比较、关注与额度动态保持免费；主动通知（邮件及未来的 IM 渠道）规划为付费服务，后续结合条件监控、合并摘要及投递可靠性完善，暂不开放或承诺具体渠道、价格与实时性。首版不展示会员、通知预告或付费入口。

`src/main.jsx` 的 `NOTIFICATIONS_ENABLED` 当前为 `false`，统一隐藏桌面/手机导航、侧栏推广、标题操作、基金列表/详情、额度动态和口径说明中的通知入口，前台也不再轮询订阅接口。站内“我的关注”仅用于收藏基金，继续保留。

此开关仅控制前台展示，不是付费权限校验，也不关闭现有订阅 API、验证/退订页面或后台邮件任务。邮件实现与数据库保留；未来正式开放付费通知前需补服务端权限、真实投递验收及具体渠道接入，不能只打开界面开关。

```dotenv
MAIL_REPLY_TO=
```

当前本地 Key 已从 tomcatTravel 的 `.env` 写入本项目私有 `.env`，原项目未修改。发件地址由用户确认。本地 Key 不能查询域名列表（`restricted_api_key`），因此本次没有独立确认域名状态，也没有实际发送测试邮件。代码使用模拟 HTTP 测试验证投递流程；配置齐备不等于真实投递已验证。

缺少 Key、发件人或站点地址时，返回 `awaiting_configuration`。配置齐备后发送确认邮件；用户点击并确认后才收到变化通知。验证码48小时有效、一次性，提醒邮件带退订链接。本地确认链接只能在运行本服务的电脑打开；公网运行前把 `PUBLIC_BASE_URL` 改为网站 HTTPS 域名。

Resend 的每封邮件使用持久化请求内容和独立的 `qdii-radar/` 幂等 Key；普通重试最多5次，间隔指数退避。429遵循 `Retry-After`，持久化全队列冷却；不可恢复的4xx终止重试。首次尝试超过23小时停止自动重试，避免超出服务商24小时幂等窗口后重复发送。服务商返回邮件ID才记为 `sent`（已接受，不代表已进入收件箱）。发送速率限制为每秒1次；与 tomcatTravel 共用 Key 时仍共享账户限额。

也支持 `MAIL_TRANSPORT=smtp`，配置 `SMTP_HOST`、`SMTP_FROM` 及认证信息；`MAIL_TRANSPORT=disabled` 显式关闭发送。SMTP在送达后断线的极端情况不能保证严格 exactly-once。

订阅通过 HttpOnly 会话 Cookie 归属当前浏览器，接口不会返回其他浏览器的订阅；尚未实现跨设备账号登录。验证链接的 GET 只显示确认页，POST 才激活/退订。`MAIL_TRANSPORT=file` 仅供测试，不投递外部邮件。

## 购买计算器：分步输入与本地快照

目标比例支持“无所谓比例偏标普”和“无所谓比例偏纳指”：不按已有持仓再平衡，在不降低预算达成率、不延长所选周期（尽快模式为最短可行期数）的前提下，优先使用偏好指数的额度，另一侧补足，可能只投入一种指数。指数分配先于少账户、费用和收益选基策略。月预算模式先最大化当月可投入金额，再按已有规则减少维护账户和定投计划；固定比例仍保留各指数缺口，不自动跨指数补足。

结果展示总预算及纳指、标普的预计可投入金额、达成率和缺口。月预算按所填扣款日计算；尽快投完没有指定截止日，展示完整计划可执行比例，并另列预计期数。无分配预算的指数显示“—”，不将零预算视为100%达成。不限比例的分项预算是按额度自动分配的金额。

左侧按 01 定金额、02 定时间、03 定比例、04 定购买渠道、05 定基金公司排列。时间支持每月固定投入、资金尽快投完；比例支持只买纳指、只买标普、自定义比例、无所谓比例偏标普、无所谓比例偏纳指。渠道支持代销、直销、代销+直销，保留已核验的跨渠道去重约束。

基金公司按完整的场外人民币纳指/标普基金名单展示，默认全选；暂停申购、暂无额度或额度待核验的公司也保留，切换购买渠道不改变公司列表。支持逐项选择、全选和清空，已保存的手动选择继续恢复；所有选基策略及长期费用情景都遵守该范围，实际方案只使用当前可用额度。移除是否开户和新开户数量逻辑。小额度开关默认关闭，代销、直销均排除日限额≤10元的候选；开启后纳入，不再判断预算占比或注册状态。

成功计算后，将输入、公司选择、手选份额、方案偏好、结果及额度签名写入本浏览器 localStorage（`qdii-radar:purchase-calculator:v1`）。修改输入但未计算不会覆盖上次快照。旧的“无所谓比例”快照恢复为偏标普并提示重新计算，不直接呈现改变后的计划。旧“资金稳健分批”快照保留金额等输入，切换为“资金尽快投完”，打开条件面板要求核对后重新计算。再次打开自动恢复输入；当前候选签名一致时重新计算并恢复结果，额度、费率或基金变化时提示重算，不将旧快照当成现行计划。存储损坏或不可用时安全回退，并在保存失败时提示；这些输入和快照不上传服务端。

结果区按“01 能不能完成 → 02 选基与费用 → 03 需要购买几个产品 → 04 最终方案”排列。完成情况包含分项预算、缺口与投完时间；选基与费用区按同一持有期比较三种偏好，默认以每笔持有 1 年为假设，展示申购费加持有期年度费用及计费申请金额，年度费率仅作辅助；切换偏好保留所选持有期，产品数量区展示基金、渠道计划及账户数量；基金名称、购买金额和扣款安排只在最终方案展示，历史收益收进单只基金的可展开详情。手机端选项纵向排列，不再横向挤放基金清单和收益。

## 渠道叠加与费用（2026-10-16）

购买计算器支持「直销 + 代销」。渠道独立性和份额共享是两个不同约束：只有经公告核验的渠道独立规则才相加，每个渠道内部仍按份额共享池去重。`server/channel-scopes.mjs` 当前确认大成纳指 A/C、建信纳指 A/C、万家纳指 A/C 的渠道独立。万家每个渠道内 A/C 合并计算，当前核验为直销100 + 代销10，不按截图的代销20或多个代销平台相乘。其他渠道关系未知时只选一个渠道，保持保守；新额度公告出现时撤销旧的叠加资格，重新核验。概览卡片和历史统计继续展示单渠道小计，不直接相加。

天天 `FundMNBasicInformation` 的 `MAXSG`、`RATE`、`SOURCERATE` 分别提供平台额度、优惠申购费率、原始申购费率，没有直销与代销是否共用的字段。新增公开费率页 `https://fundf10.eastmoney.com/jjfl_代码.html` 获取管理费、托管费、销售服务费和按金额分档的申购费。接口返回的 `fees` 包含来源与采集时间；`channelScope` 包含公告依据与核验范围。页面展示每个份额的年度费率合计与申购费，详情提供费用拆分和档位。年度费率不是全部运作成本：万家A三项合计0.65%，C为0.85%；不能把同公司费率复制给其他份额。来源缺失（如国泰160213销售服务费为 `---`）保留未知，不补零。

费用计算：输入金额是含申购费的现金预算，按逐笔金额匹配档位，申购费 = 金额 - 金额 / (1 + 费率)，固定金额档按每笔收取，逐笔保留到分。尾款单独计算；显示扣费后净投入及扣费后指数比例。设定比例仍是申请金额比例，净投入比例可能略有偏离。年度三项费用以全部净投入保持不变、持有指定年限做简单估算，不是分批期间的实际费用，不额外占用现金预算，也不再从历史净值收益扣除。不模拟赎回费用、其他交易费用或净值涨跌。代销费率仅代表天天基金；直销尚无统一的个人优惠费率接口，采用标准申购费率估算并明确标注。

计算器默认“费用优先”，以每笔买入后持有 1 年作显式测算假设，可选择 1／3／5 年或仅看年度费率。同一基金、同一购买渠道内有A类时优先A，只有“少维护”在同等额度、不增加产品数量的条件下优先C；手选份额保持不变。共享池先保留最大可用额度，独立份额不因偏好被删除，必要时补足预算。不同基金之间仍按方案的费用或历史收益排序，不以份额字母替代基金比较。选定持有期后，所有偏好都按相同期限展示申购费与持有期年度费用，切换偏好不清空期限，并继续遵守份额偏好；费用优先是排序规则，不是全局最低成本保证。费用缺失或过期时仍显示待确认，额度、渠道关系或费率改变会使旧计划失效。

常规同步同时刷新费用；失败保留旧值和原时间。已有数据库可执行 `node scripts/refresh-fees.mjs` 单独补齐，不改变额度/行情时间、不发邮件。

### 合并额度概览与排序

顶部新增「合并可买总额度」，原直销、代销保留为渠道小计。先在每个渠道内按份额共享池去重，再将已确认独立的渠道相加；共用或关系未知的重叠组只使用其中一个渠道的额度。关系未知时明确标为保守合计，不能将两张渠道小计直接相加。

过去20个交易日使用每天自己的额度、份额范围和渠道关系；每日历史数据附带 `channelScope`，旧数据缺少这一字段时不借用今天的独立关系。万家9月9日渠道独立、9月10日起全渠道共享、9月23日起分别规定渠道限额，已纳入按日期生效的规则。缺失历史不当零，只有已知部分进入累计，显示覆盖范围。未来20个交易日是当前合并额度 × 20 的静态预估，假设限额不变，不承诺实际可买金额。

年度费率、代销申购费率、渠道关系可通过表头和排序下拉框切换顺序。费率按数值排序（零费率有效），缺失或过期费率在两个方向都排在最后；渠道关系可选择可叠加优先或共用优先，未知关系始终置后。费率和渠道拆为两列，表头与单元格统一居中。

### 计划达成率与补齐时间

计算结果使用一张达成率卡片，所有状态（完整、部分、无额度）均展示预计达成率、预算、可投入金额和缺口。金额可投完但已有持仓导致目标比例无法达到时，金额达成率仍为100%，比例未达成单独标明。

紧接着按纳指、标普展示分项达成率及补齐时间。`horizonPeriods` 是本月计划扣款日或分批周期的扣款次数；分项 `extraPeriods` = 向上取整（周期结束时缺口 ÷ 本方案每期投入），从设定周期结束后开始计算。每日模式按每周5个可申购日向上折算 `extraWeeks`，每周一次则一期为一周；两个指数并行投入，总补齐时间取较慢一侧。无额度时额外时间为未知，未分配预算时不计算分项达成率。原 `periods` / `estimatedWeeks` 仍表示从开始到投完的总时长，不能当作周期结束后的额外等待时间，也不能将两个取整后的周数相减。

例：月预算10000元、各指数50%、20次扣款，纳指每日250元、标普每日120元。可投入7400元，达成率74%；纳指本月5000元可达成，标普本月2400元、缺口2600元，计划结束后还需22个可申购日（约5周），从开始共42日（约9周）。只测算本月这笔钱；未来新增月预算不包含在补齐时间中，额度和预算不变时未投入金额会继续累积。


费用展示默认突出 1 年情景总费用，辅助列出逐笔申购费、净投入和按净投入加权的组合年度费率，并提供市值不变时每万元持仓的年度费用示例。持有年限在方案比较上方统一选择，旧快照的未设期限仍可恢复；展开「长期费用比较」可比较 1／3／5 年费用优先方案及其基金、渠道、金额差异，点击采用后才改变当前计划。情景假设每笔买入后持有相应年限、净投入市值及费率不变，不预测收益、不模拟分批建仓的实际逐日账单。未知费用不补零，过期费率明确标记。同名、同公司、同一已确认额度组且同渠道的 A/C 可用份额，在费率完整有效且存在费用交点时，按双方可用的相同单笔金额提示持平时间；不含赎回费和净值变化。

### 总览小额度筛选与方案贡献度

基金总览右上角的「剔除 ≤10 元额度」开关默认打开。按每个份额、每个渠道的单日有效额度（含共享上限）筛选，保留较大额度的另一渠道；合并总额、渠道小计、指数分项、分组排序、份额历史累计和未来20交易日预估统一更新。历史按每一天的额度筛选，不以今天的额度回写历史；未知额度仍保持未知。基金份额保留供核对，小额度标为「已剔除」，详情仍展示原始来源数据。场内ETF和购买计算器的独立小额度设置不受影响。

最终方案按基金代码汇总跨渠道的累计申请金额，以「基金累计申请金额 ÷ 方案已安排总金额」展示贡献度并降序排列；渠道扣款安排分别保留。未安排的预算缺口不计入分母，百分比不是收益贡献，显示时保留一位小数。修改条件抽屉使用460毫秒侧滑与淡入，遵守系统减少动态效果设置。所有页面顶部固定显示「投资有风险，入市需谨慎」，右侧可关闭；当前浏览器记住关闭时间，24小时后恢复显示，刷新、切换页面及同源标签页共享该状态。

dashboard 接口响应缓存在当前浏览器 localStorage（`qdii-radar:dashboard:v1`）；首次没有有效缓存时读取后台，之后在北京时间下一次07:30（随服务端早间配置调整）或16:30采集时间到来前，刷新页面、重新打开和切换标签页均直接使用本地数据，不请求 dashboard。到点缓存失效并读取服务器；有效期以原请求时间固定计算，读取缓存不会续期。切回页面时也会检查过期，避免后台节流或设备休眠错过刷新。缓存只保存公开看板，保留原数据时间，不保存账号或订阅；损坏或旧版本缓存回源，浏览器禁止存储或容量不足时使用内存缓存，重新打开后正常回源。检测到正在同步时，每15秒读取分批结果，顶部显示当前阶段和该阶段进度，完成后恢复定时读取；定时窗口开始的90秒内会短暂复查，避免页面读取早于后台启动而漏掉整轮同步。首次加载尚未发现任务或接口请求失败时也会重试。更新中的缺失字段标为待补齐/核验，保留可用值和原始日期。页面读取不触发后台采集。


## 访问统计（Umami Cloud）

浏览器直接向 Umami Cloud 上报，业务服务器不接收、不代理、不存储访问事件，也不新增统计数据表。`GET /api/public-config` 仅提供公开 Website ID，不暴露任何密钥。生产环境启用；开发环境和未配置 ID 时均不加载统计脚本。

1. 在 https://cloud.umami.is/ 创建账号和网站，填写正式域名，从网站设置的 Tracking code 获取 `data-website-id`。
2. 在部署环境设置 `UMAMI_WEBSITE_ID=你的网站UUID`（或写入服务器 `.env`）。这不是 API Key，不需要配置密钥。
3. 重启生产服务；Docker Compose 使用 `docker compose up -d --force-recreate` 重新读取环境变量。ID 在运行时读取，无需为修改 ID 重新构建前端。
4. 访问正式站点，在 Umami 网站看板确认数据。选择一致的日期范围及 Asia/Shanghai 时区。

| 要看什么 | Umami 中的对应数据 |
|---|---|
| PV / UV | 页面浏览量 / Visitors；页面路径为 `/`、`/calculator`、`/changes`、`/alerts` |
| 主导航 Tab 点击量 | `tab_navigation_overview`、`tab_navigation_calculator`、`tab_navigation_changes`、`tab_navigation_alerts` |
| 交易方式 Tab 点击量 | `tab_venue_otc`、`tab_venue_etf` |
| 指数 Tab 点击量 | `tab_index_all`、`tab_index_nasdaq`、`tab_index_sp500` |
| 点击计算的次数 / 人数 | `calculator_calculate_click` 事件次数 / 按此事件筛选后的 Visitors（去重访客） |

首次打开、刷新、实际切换主页面各计一次 PV。重复点当前导航只计点击，不增加 PV；交易方式、指数筛选不增加 PV。桌面和手机导航合并到同名事件。计算事件在用户点击「生成方案」或键盘触发按钮时记录，包含输入校验失败的尝试；自动恢复快照、切换选基偏好不计计算点击。不要把计算点击次数当作点击人数。

UV 及事件人数采用 Umami 的匿名会话识别口径，不发送自定义用户身份，不等于跨设备实名人数；网络、浏览器及 Umami 的去重周期都会影响识别。统计脚本被屏蔽或请求失败会少记，但不影响计算和页面操作。输入金额、已有持仓、计算结果、搜索词、URL 查询参数不进入事件；仅发送页面和固定 Tab 标识。不启用会话回放。Umami 官方口径参考：https://docs.umami.is/docs/metric-definitions 。

购买计算器首次使用（或快照损坏时）默认选择「每月固定投入」。有效历史快照仍恢复用户上次的投入模式。

新增验证：`node --test test/usage.test.mjs test/purchase-snapshot.test.mjs`。浏览器验证先 `npm run build`，再 `node scripts/usage-smoke.mjs`（可用 `PLAYWRIGHT_MODULE` 指定模块路径）；测试使用临时数据库并拦截 Cloud 请求，不向真实 Umami 写入测试数据。可通过 `UMAMI_TRACKER_FILE` 传入已下载的官方 tracker 脚本，对真实 SDK 行为作隔离验证。

### 网站图标

`public/favicon.svg` 使用蓝底雷达标识；`favicon.ico` 包含16、32、48、64、128、256像素版本，`apple-touch-icon.png` 用于手机书签。修改 SVG 后可执行 `node scripts/generate-favicon.mjs` 重新生成（可用 `PLAYWRIGHT_MODULE` 指定 Playwright 路径）。Docker 构建会复制 `public`，Vite 将图标输出到站点根目录。

### React Bits 组件源与额度动效

项目的 `components.json` 已注册 `@react-bits`（`https://reactbits.dev/r/{name}.json`），通过官方 shadcn MCP 搜索与读取组件。Codex 用户配置安装命令为 `codex mcp add shadcn -- npx -y shadcn@latest mcp`；重启 Codex 后加载新增工具。

仅三张概览卡片顶部的大号每日额度保留动画，指数分项、历史累计和未来预估直接更新数字。额度动画基于 React Bits `Counter-JS-CSS`，本地源码及授权保留在 `src/components/react-bits/`。金额变化时按增减方向滚动变化数位，保留弹簧速度以衔接快速切换；首次展示仅短距离落位，小额度开关切换但金额不变时仅个位做轻微反馈。沿用自然字宽与现有卡片字号，千分位不滚动；未知额度保持「—」。系统减少动态效果时直接显示最终值。浏览器验证：构建后运行 `node scripts/quota-animation-smoke.mjs`（支持 `PLAYWRIGHT_MODULE`）。
